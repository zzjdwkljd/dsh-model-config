## 用户报告

1. 信息太平、文字层级弱，容易疲劳。
2. 模型右侧几类操作未对齐。
3. 测试消息位置不合适。
4. 「添加模型」弹窗遮住整个页面，边角呈方形。

## 源码定位与初步原因

- MCF_CSS 混合了原样式、演示视觉覆盖和插件追加规则，辅助信息字小且灰度过浅。
- renderModel 的说明、开关、思考/测试组合与删除按钮由不同 Grid 行列规则定位，删除跨两行，不能共享列基线。
- 测试结果位于 mcf-modelBlock，但有边框的视觉卡片只是内部 mcf-modelRow，消息因而漂在两张卡片之间。
- 视觉覆盖中的 mcf-scrim 是不透明浅色/深色；modal 未裁剪内部标题/底栏背景，圆角被子元素盖住。
- 接口信息的横线是原数据缺失占位；不捏造实际地址、协议或密钥。

## 实施计划

1. 提高文字对比与字号层级，增强提供商选中态与接口分组，保持原主色 #635BFF。
2. 用独立列统一名称/ID、识图、思考、测试、删除；窄容器自适应，保留事件与禁用条件。
3. 把成功/失败结果内嵌到对应模型卡片，保留原请求和结果文字。
4. 使用半透明遮罩、圆角裁剪和可滚动弹窗正文，保留底下的主页面。
5. 类型检查、构建、业务函数保留审计与真实组件受控宿主 UI 回归；不使用真实凭据、登录态或实际模型调用作探针。

## 交接

### 实际修改

- `src/client.ts` / `client.js`：提高主/次文字对比，区分提供商显示名与路由，补齐默认选中态；接口信息按三项技术字段、状态/上下文分组。
- 原来取不到的只读字段显示「未提供」，不硬填 URL、协议或密钥引用；数据读取来源没有改变。
- 名称/ID、识图、思考、测试、删除用独立固定列，窄宿主面板按容器宽度自适应。没有思考开关的内置提供商保留原行为，仅显示非交互占位。

- 弹窗使用半透明遮罩，主页面仍可见；圆角裁剪内部背景，限制最大高度并允许正文滚动；输入、测试、取消、关闭、添加仍为原控制器。
- 暗色主题主按钮及选中提供商头像文字保持白色，避免旧规则把蓝底文字改黑。
- 保留原主色 #635BFF，未新增生产依赖，未改 Host 源码、Host 产物或 tsconfig。
